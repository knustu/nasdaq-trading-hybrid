# 회원 관리형 스캘핑·스윙 자동매매 v2.0.1 Hybrid

Python과 C++을 역할에 맞게 분리한 Windows용 프로젝트입니다.

- **Python:** GUI, SQLite, 시세, 기술지표, XGBoost, 증권 API
- **C++:** 진입 판단, 청산, 트레일링, 주문수량, 모의체결 및 손익 계산
- 연결 방식: **pybind11 인프로세스 호출**

로컬 HTTP 서버나 별도 Python 프로세스를 띄우지 않으므로 통신 지연, 포트 충돌, 프로세스 종료 문제를 줄였습니다.

## 0. 가장 쉬운 실행 방법

ZIP 파일 안에서 배치파일을 직접 실행하지 말고 먼저 **압축 풀기**를 해야 합니다. 압축을 푼 폴더에서 아래 파일 하나만 실행하면 됩니다.

```text
START_HERE.bat
```

설치가 안 되어 있으면 자동으로 설치한 뒤 앱을 실행합니다. 모든 배치파일은 이제 자신의 위치로 작업 폴더를 자동 변경하므로, 바탕화면 바로가기나 다른 경로에서 실행해도 프로젝트 파일을 찾습니다.

설치 도중 C++ 컴파일러가 없으면 Python fallback으로 앱을 먼저 실행할 수 있게 설정합니다. 이후 Visual Studio Build Tools를 설치하고 `build_cpp.bat`을 실행하면 C++ 하이브리드 엔진이 활성화됩니다.

문제가 계속되면 `diagnose_windows.bat`을 실행해 Python, 가상환경, C++ 엔진과 Visual Studio 설치 상태를 확인합니다.

## 1. 먼저 설치할 것

1. 64비트 Python 3.11
2. Visual Studio 2022 Build Tools 또는 Visual Studio 2022
3. Visual Studio Installer에서 **Desktop development with C++** 선택
4. MSVC v143, Windows 10/11 SDK 설치

## 2. 설치

압축을 푼 폴더에서 다음 파일을 실행합니다.

```text
install_windows.bat
```

이 배치파일은 다음을 자동으로 수행합니다.

1. `.venv` 생성
2. Python 패키지 설치
3. C++ 엔진 컴파일
4. C++ 모듈 로드 확인
5. 자동 테스트 실행
6. `.env.example`을 `.env`로 복사

설치 성공 메시지가 나온 뒤 실행합니다.

```text
run_app.bat
```

콘솔 버전은 다음을 실행합니다.

```text
run_cli.bat
```

## 3. 설치 중 C++ 빌드 실패

다음 명령만 다시 실행할 수 있습니다.

```text
build_cpp.bat
```

`Microsoft Visual C++ 14.x is required`와 비슷한 오류가 뜨면 Visual Studio Installer에서 C++ 데스크톱 개발 도구가 빠진 것입니다.

## 4. 프로그램 흐름

```text
회원가입 또는 로그인
  -> 스캘핑 / 스윙 선택
  -> PAPER / LIVE 선택
  -> 진입 기준과 위험 설정 저장
  -> 1회 실행 또는 연속 실행
```

사용자별로 다음 정보가 SQLite에 저장됩니다.

- 비밀번호 해시
- 선택 전략과 거래 모드
- 위험 설정
- 모의 현금
- 포지션
- 주문 및 거래내역

## 5. 전략별 데이터

### 스캘핑

- 봉 간격: 1분
- 모델: `models/scalping_xgb_model.json`
- 메타데이터: `models/scalping_xgb_model.meta.json`
- 기본 반복 주기: 15초

### 스윙

- 봉 간격: 1시간
- 모델: `models/swing_xgb_model.json`
- 메타데이터: `models/swing_xgb_model.meta.json`
- 기본 반복 주기: 5분

두 모델은 서로 바꿔 사용할 수 없습니다. 메타데이터의 전략과 봉 간격이 맞지 않으면 로드를 거부합니다.

## 6. 모델 학습

```text
.venv\Scripts\activate
python train_models.py --strategy SCALPING
python train_models.py --strategy SWING
```

AI 학습과 추론은 Python/XGBoost가 담당합니다. 최종 진입 확률은 C++에서 아래 방식으로 결합합니다.

```text
최종확률 = AI 확률 × 0.75 + 규칙 점수 × 0.25
```

검증된 AI 모델이 없을 때:

- PAPER: 규칙 점수만으로 테스트 가능
- LIVE: 진입 차단

## 7. 진입 시간 제한

기본값은 시간 제한이 없습니다.

```env
RESTRICT_ENTRY_TO_REGULAR_SESSION=false
```

프리마켓, 정규장, 애프터마켓에서 새 봉과 데이터 신선도 및 진입 확률을 기준으로 판단합니다. 정규장으로 제한하려면 `true`로 바꿉니다.

시간 제한을 없애도 다음 안전장치는 유지됩니다.

- 오래된 데이터 차단
- 같은 봉 중복 판단 차단
- 일일 최대 매수 횟수
- 최대 동시 보유 종목 수
- 위험예산 기반 수량 제한
- 손절, 익절, 트레일링 및 최대 보유시간

## 8. C++ 엔진 확인

GUI 대시보드 상단에 다음처럼 표시되어야 합니다.

```text
계산 엔진: C++/2.0.1-hybrid
```

아래처럼 표시된다면 C++ 모듈이 로드되지 않은 것입니다.

```text
계산 엔진: PYTHON_FALLBACK
```

기본 `.env`의 `REQUIRE_CPP_ENGINE=true`에서는 fallback 상태로 앱이 시작되지 않습니다.

## 9. 실거래 주의

기본 모드는 PAPER입니다. LIVE는 다음 조건을 모두 충족해야 합니다.

- `.env`의 `ALLOW_LIVE_TRADING=true`
- 공식 토스증권 액세스 토큰과 계좌 식별값
- 최신 공식 문서의 잔고 및 주문 상태 경로
- 계좌의 프리마켓/애프터마켓 주문 지원 여부 확인
- PAPER 모드 장기 검증

포함된 실거래 어댑터는 계좌별 최신 API 명세와 실제 응답을 사용자가 다시 검증해야 합니다. 주문 상태가 불명확하면 자동 재주문하지 않고 거래를 중단합니다.

## 10. 테스트

```text
run_tests.bat
```

테스트 범위:

- 회원가입 및 로그인
- 중복 회원 차단
- 전략 변경 안전장치
- 모의 매수/매도와 초과 매도 차단
- AI 라벨 미래 데이터 누수 방지
- 진입 시간 제한 기본 해제
- Tkinter 내부 메서드 충돌 방지
- C++ 진입·청산·수량·체결·손익 계산

```text
tests/               자동 테스트
```
